The Brain / Capabilities / Filing artifacts

ACT

An artifact filed nowhere
is an artifact nobody will find again.

Most assistants can make you a deck, which then lives wherever the tool put it, disconnected from the engagement. The Brain creates and files in one action, into the folder that already holds the client, across its own 12 application surfaces and 190 business objects.

What changes on Monday: what gets created is born next to the brief it was built from, so the next question about that client returns it without anyone searching.

What it looks like on a Tuesday

A review deck nobody has to go looking for

10:02

The source material is read from the folder, not searched for

The engagement folder already holds the signed brief, the tracking sheet, last quarter’s deck and the thread where scope moved in July. They are together because they were filed when made.

10:04

The deck is created into the folder, not into a tool

A real deck in the presentation application, editable there, and a child of the client folder from the moment it exists. Nobody names a file and nobody moves it afterwards.

10:12 · a person confirms

Sharing it outward waits for a click

Creating and filing are ordinary writes. Sharing is one of the 71 actions that stop for a person, so the deck sits complete until the director approves sending it.

How it works

Three mechanisms

01

The folder is the container, and each application keeps its own artifacts

Nothing is merged into one blob store. A folder holds a mixed set and every item opens in the application that understands it. Filing costs an application a declaration, not the Brain a rewrite.

02

Filing is what makes later recall cheap

Because the folder is one readable scope, a question about the client reads one place instead of five searches merged. That is the difference between finding a document and answering about an engagement.

03

Everything filed is fenced to your organization

The folder an artifact lands in is resolved from the verified session, never from a value the model wrote, and every memory fact names the organization it belongs to.

What it is not

Three honest limits

It is not a document management system. It files what it creates; it does not reorganise twelve years of shared drives.

The applications that have declared it are the ones this covers today, and we say which before the engagement starts.

It cannot file into a structure that does not exist. The first thing an engagement decides is what the container for a client is, and who may see it.
