The Brain / Capabilities / Read after write

PROVE

A write that reports success
is not believed on its word.

Every mutating action returns a result that says whether it worked, written by the same code that just ran, which makes it a self-report. Before the Brain tells a person the thing is done, it goes back and looks for the record.

What changes on Monday: if the invoice was raised, a second read found the invoice. If it was not, the update says so, instead of somebody discovering the gap when the client asks.

What it looks like when it fires

A task that was reported created, and was not

01

The action runs and returns success

The create call reports success and hands back an identifier. Nothing is wrong on its face, and that payload is what most assistants would narrate.

02

The identifier is looked up again, scoped to the session

The lookup carries the organization from the session, never from anything the model wrote. The write had landed on a project archived that morning, so the row is not there.

03

The person gets a problem while it is still small

The success flag is flipped before the reply is drafted. The lead reads that the task was not created, and why, now rather than at Thursday’s review.

How it works

Cheap, fenced, and bounded by a clock

01

Cheap enough to stay on for every write

Verification that slows a turn gets switched off, and a check that is off protects nothing. This is one cheap read on a short budget; when the clock runs out it abstains.

02

No model call, so it cannot be talked out of it

The check is a lookup, not a judgment. It has no opinion about the content and no prompt to be persuaded, so it cannot inherit the misreading it is checking.

03

The fence is part of the lookup, not a filter after it

Identity comes from the session, never from the model, so the identifier being checked cannot be paired with an organization the model named.

What it is not

Three honest limits

It does not check that the change was correct. A task created with the wrong assignee passes, because the row exists.

It cannot help when an action returns nothing to re-read. That case abstains, and the tool’s own report stands.

It proves the record was there when it looked, nothing further, and it needs read access on whatever the Brain may write.
