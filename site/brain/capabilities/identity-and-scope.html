The Brain / Capabilities / Identity and scope

CONNECT

Who is asking is never something
the model gets to decide.

Every action carries a user and an organization, and both are read from the session that made the request. Whatever the model produced in their place is discarded on the way into every call, so identity is never something it gets to argue for.

What changes on Monday: the first question your security reviewer asks, what this can reach and on whose behalf, has an answer that does not depend on the model behaving.

What it looks like when it fires

A document that tries to move the fence

01

An inbound attachment carries an instruction, not just content

Buried in a supplier document is a line telling the assistant to look up addresses held for a different account. Plain text, nothing malformed, nothing between sender and reader built to notice.

02

The model reads it and is persuaded

Assume the worst honest case: the model drafts a call naming a different organization. No amount of prompt hardening removes this step reliably, so the design does not rely on the model declining.

03

The identity is replaced before the call is made

The organization the model named is discarded and the session’s written in. The read comes back scoped, and the person gets a summary of the document they were sent.

How it works

The same rule, applied in three places

01

Overwrite, rather than validate

The tool layer does not inspect the identity the model supplied and decide whether to trust it. It replaces it. Validation can be wrong on an input nobody anticipated; overwriting has no branch.

02

The organization is part of the query, not a filter afterwards

A read asks for rows belonging to one organization rather than asking for rows and discarding some. Most of the data layer carries that boundary today, and the rest is being brought in.

03

Memory is fenced on the same axis, and an unfenced check refuses

Every memory fact names the organization it belongs to. Where a verification step has no organization to scope on, it answers indeterminate rather than passing.

What it is not

Three honest limits

It is not a certification. No SOC 2, no ISO 27001 is claimed, and data handling terms are agreed per engagement in writing before anything connects.

It does not mirror the permissions of your source systems. Nothing we measure covers permission fidelity, so we do not claim it.

Not all of the data layer carries the boundary yet, and we would rather say so than round it up. A service identity per connected system is what we ask of you.
