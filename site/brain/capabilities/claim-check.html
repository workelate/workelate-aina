The Brain / Capabilities / Claim check

PROVE

The sentence is measured against the data,
not against what you asked for.

Ask for a thing to be updated and the natural closing sentence is that it has been updated, whether or not the data says so. The drafted reply is compared to what the tools actually returned in that turn, never to the request.

What changes on Monday: the phrase “I have updated it” stops being free. If the update matched no rows, the reply says so, in the same message.

What it looks like when it fires

A field update that matched nothing, narrated as done

01

The update reports success with nothing modified

The filter picked an account identifier superseded by a merge last quarter. The store answers truthfully: the operation succeeded, and it changed zero records. Both facts sit in the payload.

02

The draft says the date has been moved

This is the ordinary failure. The reasoning step saw a success flag and a request to move a date, and wrote the sentence those two facts imply.

03

The sentence and the data disagree, so the sentence loses

The claim asserts a changed date; the payload carries a modified count of zero. The reply the manager reads says the update matched no records and names the identifier it tried.

How it works

A cheap judge with a narrow question and an exit

01

It compares to payloads, because payloads cannot be persuaded

The evidence is the structured result of the calls that ran. Text the model read earlier, including anything an inbound mail said about itself, is not evidence of what changed.

02

Abstaining is a first-class answer

The judge answers in a fixed shape and is allowed to say it cannot tell. That keeps it from inventing a verdict on a turn where the evidence is genuinely ambiguous.

03

One re-draft, then a plain correction, never a silent ship

The model gets one attempt, holding the data. If that still does not match, a correction goes out written by code, not by the model that just missed twice.

What it is not

Three honest limits

It does not grade whether the action was a good idea. A correctly narrated bad decision passes cleanly.

It runs only on turns where something changed and the reply claims completion. A conversational answer is not checked by it.

It is a judge, so it can be wrong, and it is built to err towards letting a true claim through rather than blocking a healthy turn.
